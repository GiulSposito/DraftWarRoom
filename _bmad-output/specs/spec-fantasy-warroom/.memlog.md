- (direction) Source: docs/fantasy-warroom-bmad-intent.md is the authoritative intent; it supersedes earlier designs now in docs/archive/ (SQLite, event sourcing, package architecture, async workers, live Monte Carlo, multi-engine, multi-user platform). Those must not be reintroduced without an approved change.
- (decision) Treat as one spec-backed epic implemented through eight small independently reviewable stories; no PRD, project architecture, traditional epics, sprint-status.yaml, or sprint-planning artifacts.
- (decision) Spec folder slug: fantasy-warroom.
- (capability) CAP-1 Pre-draft projection preparation: prepare.R turns ffanalytics multi-source scrapes into an immutable normalized snapshot with league-custom Full-PPR scoring; raw scrape saved separately for rebuilds.
- (capability) CAP-2 Synthetic projection fixture: core dev and tests run against a synthetic projections snapshot with no live scrapers and no network.
- (capability) CAP-3 Snake schedule generation: full 12-team x 14-round pick order, 168 picks, correct serpentine reversal.
- (capability) CAP-4 Draft state creation, persistence, recovery: create or resume a draft; every accepted pick persisted atomically with a backup of the prior state; stop and resume safely.
- (capability) CAP-5 Derived draft views: current pick, team on the clock, rosters, available players, best lineup, and user's next pick are derived from the ordered picks alone; none persisted.
- (capability) CAP-6 Pick validation and undo: no double-draft, drafted player_id must exist in snapshot, picks cannot exceed teams x rounds, undo removes only the most recent pick and restores availability.
- (capability) CAP-7 Operational terminal draft loop: interactive REPL with player-name resolution (exact/substring/prefix/fuzzy + numbered disambiguation) and commands /rec /board /board <pos> /team /teams /undo /status /save /quit; auto-shows recommendations on the user's turn.
- (capability) CAP-8 Roster-aware recommendation foundation: rank available players by roster marginal value + VOR + positional tier, apply feasibility guardrails, attach deterministic label and rule-generated explanation.
- (capability) CAP-9 Market-aware wait intelligence: p_next (conditional ADP survival), expected best alternative next pick, wait cost, tier cliff, ADP value, combined into a configurable weighted score; analytic and deterministic, no live Monte Carlo.
- (capability) CAP-10 Mock simulator and calibration: seeded complete mock drafts with ADP-driven opponents; compare adp/vor/warroom strategies on documented metrics; transparent weight-grid calibration; all rosters valid.
- (capability) CAP-11 Thin Shiny War Room: single operational page over the same core functions and RDS files; terminal and Shiny produce identical recommendation order for the same state; no duplicated formulas; sub-second refresh; no network in live path.
- (constraint) R is the only application language; runtime data and persistence use RDS only.
- (constraint) ffanalytics may be called only by scripts/prepare.R, never while a live draft runs; the live path (R/ core, scripts/draft.R, app.R) makes no network calls.
- (constraint) Business rules live in plain functions under R/ and must not depend on Shiny; scripts/ and app.R are adapters over the same functional core.
- (constraint) Persist only the ordered picks (overall, player_id, entered_at); current pick, rosters, availability, lineup, recommendations are always derived, never persisted. Next overall pick is always nrow(picks)+1.
- (constraint) data/projections.rds is immutable for the duration of a draft.
- (constraint) State saves are atomic: write temp file, keep a backup of previous state, rename into place; every accepted pick saves immediately.
- (constraint) No SQLite or other DB, event sourcing, R6, golem, targets, Docker, API, authentication, background workers, or dependency-injection framework.
- (constraint) No live Monte Carlo in the recommendation path; wait-cost math is analytic and deterministic. Same snapshot + config + pick state yields the same recommendation order.
- (constraint) Dependencies minimal and pinned with renv, including a pinned version/commit of ffanalytics.
- (constraint) Terminal draft and simulator are complete and working before any Shiny work begins.
- (constraint) Only the initial league format needs full validation this epic: 12 teams, 14 rounds, roster QB1/RB2/WR2/TE1/FLEX1(RB or WR)/K1/DST1, bench 6, Full PPR, draft order entered immediately before the draft, user team and slot configurable in config.R.
- (constraint) Eight stories implemented in the fixed order from the intent's Required story order; no story implements work belonging to a later story. Human checkpoint required for stories 1, 3, 5, 6, 8.
- (constraint) Recommendation guardrails: no K/DST before the final rounds unless mandatory; penalize QB2 strongly and TE2 while starters/FLEX open; preserve greater bench option value for RB/WR; when remaining picks equal remaining mandatory slots only feasibility-preserving positions are eligible. Recommendations must never make completing mandatory roster slots impossible and must contain only available players.
- (constraint) Explanations and labels are generated by deterministic rules, never an LLM call. Labels include TAKE NOW, BEST VALUE, CAN WAIT, TIER CLIFF, ROSTER NEED.
- (constraint) Interpret ffanalytics floor/ceiling/sd as dispersion across projection sources (source_low/source_high/source_sd), not a full probabilistic season model; give this small weight.
- (constraint) Live recommendation refresh should normally complete well under one second, targeting ~300 ms on the dev machine.
- (decision) Non-goals: multi-user collaboration; cloud deployment; multiple simultaneous drafts; automatic fantasy-platform sync; live injury/news ingestion; live projection scraping during a draft; universal scoring/roster-rule support; historical-season backtesting; ML or genetic recommendation optimization; mobile-first design; a polished public product.
- (decision) Success signal: one person can (1) generate or load a projection snapshot, (2) configure the 12-team draft order, (3) conduct all 168 picks in the terminal stopping and resuming safely, (4) get fast deterministic explainable recommendations on every personal pick, (5) run seeded mocks comparing ADP/VOR/War Room, (6) conduct the same draft in Shiny with the same recommendations as the terminal core.
