# Recommendation algorithm

Companion to `SPEC.md`. Covers CAP-8 (foundation) and CAP-9 (market-aware). The first production algorithm is transparent and fast: four understandable components combined with configurable weights, not a black-box optimizer. All math is analytic and deterministic — no live Monte Carlo.

## Component 1 — Roster marginal value

Best current lineup for a roster:

- best QB
- best two RBs
- best two WRs
- best TE
- best remaining RB or WR as FLEX

For each candidate:

```
marginal_value = lineup_value(roster + candidate) - lineup_value(roster)
```

A candidate who would sit on the bench instead receives a discounted option value driven primarily by positive VOR. RB and WR bench options retain more value than QB2 and TE2 because they cover more starting and FLEX situations.

## Component 2 — Probability of surviving to the user's next pick (`p_next`)

Use ADP as market price. Derive a configurable draft standard deviation from ADP, `adp_sd`, and a minimum spread. Use a **conditional** survival probability: the calculation must recognize the player is still available now.

```
p_next = P(pick >= next_user_pick) / P(pick >= current_pick)
```

with a normal approximation for the pick distribution, result bounded to `[0, 1]`. `p_next` is an operational decision aid, not a calibrated probability.

## Component 3 — Expected best alternative next time

For each position, sort available players by value and use their `p_next` values to compute the expected value of the best survivor at the user's next pick, analytically and deterministically.

```
p_best(j) = p_next(j) * prod over h<j of (1 - p_next(h))
expected_best_next(pos) = sum over j of value(j) * p_best(j)
```

Simplified wait cost:

```
wait_cost = max(0, roster_value(candidate) - expected_best_next(position(candidate)))
```

## Component 4 — Tier cliff and ADP value

Use the `tier` from `ffanalytics`. Measure how many relevant players remain in the candidate's tier and the projected drop to the best available player in the next tier.

```
tier_cliff = points(candidate) - points(best available in next tier)
adp_value  = current_overall_pick - adp(candidate)     # positive = fell past market cost
```

## Combined score

Normalize each component to `[0, 1]` within the current candidate shortlist, then:

```
score = 100 * ( w_roster * N(roster_value)
              + w_wait   * N(wait_cost)
              + w_tier   * N(tier_cliff)
              + w_adp    * N(adp_value) )
```

Initial weights (calibration hypotheses, not fixed truth):

```
roster_value  0.50
wait_cost     0.30
tier_cliff    0.15
adp_value     0.05
```

## Guardrails

- Do not recommend K or DST before the final rounds unless remaining roster slots make them mandatory.
- Penalize QB2 strongly while mandatory starters or FLEX remain open.
- Penalize TE2 while higher-value starting or FLEX needs remain (slightly less than QB2).
- Preserve greater bench option value for RB and WR.
- When remaining picks equal remaining mandatory slots, only positions that keep the roster feasible are eligible.
- Recommendations never contain drafted players and never a player whose pick makes a mandatory slot impossible.

## Labels

`TAKE NOW`, `BEST VALUE`, `CAN WAIT`, `TIER CLIFF`, `ROSTER NEED`. Indicative rules: `p_next` low and score high → `TAKE NOW`; fell well past ADP → `BEST VALUE`; `p_next` high → `CAN WAIT`; last relevant player in tier → `TIER CLIFF`; fills a critical mandatory slot → `ROSTER NEED`.

## Explanations

Generated by deterministic rules, never an LLM call. Each recommendation states the most important reasons: marginal lineup gain, VOR, low `p_next`, last player in tier, ADP discount, mandatory roster need.

## Off-turn use

`recommend_players()` is coherent only for the user's own pick — `p_next`'s
conditional denominator and `adp_value` key off the current overall. Called
off-turn (e.g. `/rec` during an opponent's pick) it still returns a ranking, but
marks it (`attr(., "off_turn") = TRUE`) and prefixes the top row's `reason` with
an explicit "assumes you pick now" warning; the terminal and Shiny surface that
warning. A finished draft is not off-turn.

## Recommendation output columns

```
player_id  player  pos  points  vor  tier  adp
p_next  marginal_value  wait_cost  tier_cliff  adp_value
decision_score  label  reason
```
